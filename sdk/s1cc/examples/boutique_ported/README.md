# boutique_ported — the Roland Boutique JP-08 / JU-06 / JX-03 voice on SYSTEM-S1CC

State: 2026-11-11. The voice of the first-generation Roland Boutiques as an s1cc kernel for the SYSTEM-1
(`examples/system_s1cc`). One firmware (`BQ_UPD.BIN` 1.21) holds the three models; this example builds one model
per PLUG-OUT (`BQ_MODEL`; JP-08 done). Four builds of the JP-08 voice, from exact to cheap (§6): `JP-08-S1` (`bq.c`,
Roland's voice as is), `JP-08-S1H` (`bq_host.c`, host envelopes / LFO, §8), `JP-08-S1X` (`bq_host2x.c`,
oscillators at two sub-samples, §9), `JP-08-S1A` (`bq_arm.c`, filter coefficient and VCA on the ARM, §10; on
`examples/system_s1cc_boutique`). Nothing is written by ear: the DSP part is Roland's microcode
translated operation by operation (`dsplift.py`, [Vol. V ch. 8](../../../../docs/vol5_toolchain_compiler_sdk/dsplift.md)),
the ARM part is what Roland's ARM code writes, recorded by running it in an emulator.

| file | what it is |
|---|---|

| `bq_host.c`, `bq_host2x.c`, `bq_arm.c` | the cheaper kernels (§8, §9, §10) |
| `bq_osc2x.h` | Roland's saw / pulse at two sub-samples with an 11-tap FIR (§9; hand-written) |

| `bq_names.txt`, `bq_names_host.txt` | inputs, outputs and constant inputs of the lift, exact / host builds (§2; hand-written) |

## 1. Source

`BQ_UPD.BIN` = "Boutique System Program 1.21" (`boutique_sys_121`, 2019-09-12); its modules are named `PX-11:...`.
`PX-11:Appli` (0x40-byte header + LZSS, `tools/lzss.py`) is the ARM image, base `0x60000000`, SHA-256
`282b69e4…a202`.

```sh
python3 sdk/s1cc/examples/boutique_ported/tools/bq_extract.py BQ_UPD.BIN          # -> work/bq1 (not in git)
```

**One firmware, three models** [code]. The synth object (global `0x601c32c0`) keeps the model in byte `+0x400`:
0 = JP-08, 1 = JU-06, 2 = JX-03 (read from `[0x602eebc8 + 0x50]`; the USB name code `0x6001195c` writes "JP" / "JU"
/ "JX" by it).

**Two DSP chips, two voices each** [code]. Program memory per chip, the programs each sample runs (byte addresses):

| program | chip 0 | chip 1 | what it does |
|---|---|---|---|
| pre | `0x1000` | `0x0400` | LFO (rate, delay, 5 shapes), noise; shared by the chip's voices |
| voice | `0x1900` (A), `0x2c00` (B) | `0x1200`, `0x2500` | glide, two ADSRs, modulation, mixer, HPF, 4-pole filter, VCA |
| OSC1 / OSC2 slots | `0x3f00` / `0x4f00` (A), `0x5700` / `0x6700` (B) | `0x3800` / `0x4800`, `0x5000` / `0x6000` | one of 9 oscillator programs |
| post | `0x1400` | — | the four voices to stereo, level, soft clip |
| effects | — | `0x0800` | chorus / delay |

The 9 oscillator programs (variant table `0x60166e30`, per slot; chosen by the ARM at `0x6002a5d2`, `0x600292d6` from
the tables at `0x6006ad00` (OSC1) / `0x6006ad48` (OSC2), `[model × 6 + WAVE]`):

| variant | instructions | JP-08 OSC1 / OSC2 positions | JX-03 | JU-06 |
|---|---|---|---|---|
| 0 | 131 | 0 / 0, 3 | 0 | |
| 1 | 123 | 1 | 1 | |
| 2 | 134 | 2 (saw) / 1, 4 | | |
| 3 | 152 | 3, 4 (pulse, square) / 2, 5 | | |
| 4 | 27 | 5 (noise) | | |
| 5 | 264 (+ empty OSC2) | | | all (the DCO: saw, pulse, sub, noise) |
| 6 | 132 | | 2, 3 (saw) | |
| 7 | 152 | | 4, 5 | |
| 8 | 33 | | noise | |

**The model's immediates** [code, emulated]. At set-up the ARM rewrites immediates inside the DSP programs through an
indirect port: `0x40100900` = `0x40000000 | type << 28 | (0x50000 chip 0, 0x70000 chip 1) + byte address`,
`0x40100904` = the value; type 0 / 1 / 2 = a 16 / 24 / 32-bit immediate at that byte of the immediate stream. JP-08:
110 such writes on chip 0. The voice program is therefore not the same in the three models.

**Sample rate** [code]. The first-generation Boutique runs at **44.1 kHz** (the oscillator's phase step is
`440 / 88200` per sub-sample, four sub-samples per sample); the SYSTEM-1 at 96 kHz. The TB-03 (second generation)
runs at 96 kHz. Every per-sample constant is converted (§2, §3), r = 44100 / 96000.

## 2. The voice program (`bq_MODEL_voice.h`)

```sh
python3 sdk/s1cc/examples/boutique_ported/tools/make_voice.py jp08 2 3 --names   # names, step 1 (§2.1)
python3 sdk/s1cc/examples/boutique_ported/tools/make_voice.py jp08 2 3       # MODEL OSC1-variant OSC2-variant
```

1. The programs that make voice A of chip 0, each with the model's immediate patches (`work/bq1/MODEL_patches.json`).
2. The program's own per-sample constants converted to 96 kHz (`RATE_IMM`): gate counter step, filter frequency
   scale (`0.007836163 × r`), LFO step limit, shortest attack. The VCA level smoothing (`0.0075531`, a MAC
   coefficient) is not converted: it only smooths a constant.
3. Concatenated in this order and cut in two (`--split`): **DSP A** = pre, voice instructions 0…184 (LFO, glide,
   envelopes, modulation, the oscillators' pitch), OSC2; **DSP B** = OSC1, voice 185… (mixer, HPF, filter, VCA).
   OSC2 is on A because its output modulates OSC1's pitch (CROSS MOD). Every value flows A → B (6 values,
   `bq_import_ranges.txt`). `--zero-cells 41b`: OSC1's sync output, read on A, used only with OSC2 SYNC (off).
4. `dsplift.py --bq2 --kernel --bank1-ring --kout 203a`: the programs of one chip hand values over in bank 1, which
   is a ring as bank 0 (store at X, read X + 1 next sample; `--bank1-ring`, added for this port); `203a` is the
   voice's output to the post program. `--consts`: the parameter words no panel control moves.

Inputs (`bq_names.txt`): `A080` pitch (octaves, 4.75 = A 440: `s1_pitch()`), `A081` gate; `A090…A093` the PWM
source (`bq.c`); the rest constants:

| input | value | why |
|---|---|---|
| `A084`, `A086` | 5.5 | the envelopes are used as env² × −0.09999484 × (1 − 2a): 5.5 = +0.99995 (with 1 they were ×0.1: no audible envelope, measured on the lift 2026-11-11) |
| `A088`, `A089` | 0.459375 | the oscillators' frequency factor (the ARM writes 2^range per note): 8′ × 44100 / 96000 |
| `A08B`, `A08D` | 1 | free-running phase (0 = the sync input holds the phase: half the ramp, an octave off; measured on the device 2026-11-11) |
| `A082`, `A083` | 0 | portamento off |
| others | 0 / 1 | sync, key follow of the envelopes, the chip-1 links: off |

Envelope fix (`make_voice.py` post-passes `attack_fix`, `release_fix`): Roland's attack and decay pull on the level
in the same sample; in the lift at 96 kHz the attack stalled at 0.8925 (the end-of-attack test) and the note hung
(heard 2026-11-11). The attack now writes `t138 + t137` alone; the decay / release keep Roland's one-pole.

### 2.1 Names (two steps)

```sh
python3 sdk/s1cc/examples/boutique_ported/tools/make_voice.py jp08 2 3 --names   # step 1: bq_jp08_names.txt
python3 sdk/s1cc/examples/boutique_ported/tools/make_voice.py jp08 2 3           # step 2: the lift reads it
```

(the same with `--host`, `--host --osc2x`, `--host --osc2x --arm`: `bq_jp08_host_names.txt`, `…_host2x_…`,
`…_arm_…`). Step 1 runs `sdk/s1cc/tools/dsplift_names.py` (dsplift.md §6.4) on the same program and arguments as the
lift and writes `bq_MODEL*_names.txt`: the seeds, then a `cell X NAME` line for every other bank-0 cell. Step 2 only
reads that file: read it, correct it by hand if needed, lift again. The seeds:

1. `work/bq1/MODEL*_params.txt`, written by `make_voice.py` from the tables file: `param C05F cutoff knob` … (the
   panel controls, the same names as `s1cc check`'s knobs);
2. `bq_names.txt` / `bq_names_host.txt`: inputs, outputs, constant inputs;
3. `bq_names_cells.txt` (included by both): 36 cells whose musical role was read from the lift (`lfo`, `env1`,
   `osc1_out`, `filter_p1…p4`, `vca_out` …) and the section headings (`section @env1* …`, anchored by name, so one
   file serves the four builds whose instruction numbers differ).

Every other cell gets `GROUP_ROLE`: GROUP = the seed it flows into first (`osc1_*` for everything that ends in
`osc1_out`), else the panel group it reads (`env1_a` → `env1`), else the cells it reads; ROLE = its form (`phase`,
`lp`, `state`, `fir`, `prev`, `in`, `sq`, `recip` …; a plain number when no form is recognised). Step 1 overwrites
`bq_MODEL*_names.txt`: a correction that should stay goes into `bq_names_cells.txt`. `make_voice.py`'s post-passes
(`attack_fix`, `release_fix`, `micro_fix`, `arm_fix`) match by form and instruction number, not by name.

The names do not change the code: s1cc units with and without names are the same in the four builds (553 / 449,
797, 468, 388; measured 2026-11-12, dsplift.md §6.4).

New decoder templates (`examples/from_scratch/re/dsp_templates.txt`, 2026-11-11, from neighbouring decoded
instructions, not measured): `0x0288 MBBTNIRIII` (pre programs; same shape as the verified `0x0510`),
`0x04a8 MABBTNIRII`, `0x05ec ABBCTTTIRRR` (the saw oscillators, variants 2 and 6).

## 3. The ARM side (`bq_MODEL_tables.h`)

```sh
pip install unicorn
python3 sdk/s1cc/examples/boutique_ported/tools/bq_arm.py jp08
```

`tools/bq_fw.py` maps the image, copies what the start code copies (ITCM `0x6016725c` → `0x01000300`, `0xe97c`
bytes; `0x60175bd8` → `0x01010000`; SRAM data `0x60175c40` → `0x20000000`), replaces `operator new` (`0x6005660c`)
by a bump allocator, and records the writes to the parameter windows (`0x4014c000` chip 0, `0x4016c000` chip 1, 16
bytes per word `C000 + i`, value at +4) and to the program port. The full boot does not run (an RTOS that waits for
interrupts); instead:

| step | function |
|---|---|
| constructor of the synth object | `0x60054714` (creates the parameter sub-objects) |
| init (model byte from the global) | vtable 0 `0x6002472a` |
| model set-up (propagates the model) | vtable 3 `0x60024e1e` |
| first update (57 words, the patches) | vtable 4 `0x60024c1c` |
| a whole patch | vtable 10 `0x60024ff0` |
| one parameter | vtable 13 `0x6002b3e2` (`obj, id + 0x141, 0, value`) |

The patch parameter ids and names are tables in the image (26 bytes per entry from `0x60066b1c`: JP-08 `0x18e…`,
JU-06 `0x1d0…`, JX-03 `0x200…`). Internal id `0x108` = velocity → `C069 = (v / 127)²` (127: the SYSTEM-1 keyboard
has no velocity).

Each table row is the SYSTEM-1 knob value already mapped (`PANEL`, kinds `uni`, `bi`, `rev`, `sq`), the per-sample
words converted to 96 kHz (`RATE_WORDS`): attacks `1 − (1 − c)^r`, decay / release `(1 − (1 − 0.01 c)^r) / 0.01`, LFO
step `× r`, LFO delay factor `(0.9 + 0.1 c)^r`, HPF `1 − (1 − c)^r`.

## 6. Cost and voices

| build | DSP A | DSP B | voices |
|---|---|---|---|
| `JP-08-S1`, saw + pulse, exact | 472 | 413 | 1 (split A / B) |
| `JP-08-S1H`, host envelopes / LFO (§8) | 784 fused | — | 1 |
| `JP-08-S1X`, two sub-samples (§9) | 315 fused | — | 3 |
| `JP-08-S1A`, coefficient + VCA on the ARM (§10) | 253 fused | — | 4 |

Fused = the whole voice on either DSP (SYSTEM-S1CC `SPLIT`), so one count per voice.

Where the time of one voice goes (Roland instructions): pre 59, voice 339, each oscillator 123–152 (four
sub-samples per sample and a 28-tap decimation FIR). Ways to more voices, by gain:
1. the oscillators at two sub-samples (96 kHz × 2 = 192 kHz, more than Roland's 176.4 kHz): ~130 per voice;
2. envelopes and filter coefficients on the ARM (1 ms ramps): ~130 per voice, not sample exact;
3. pre (LFO, noise) once for all voices, as Roland: ~50 per voice.
Done: 1 (§9) and 2 (§10). Goal: 8 voices = about 125 instructions per voice.

## 8. Host envelopes and LFO (`bq_host.c`, `make_voice.py --host`)

The voice without Roland's LFO and envelopes: SYSTEM-S1CC's take their place (`s1_env(0)` AMP, `s1_env(1)` FILTER,
`s1_lfo_filter()`, the LFO and PITCH ENV in `s1_pitch()`). `--host` drops the pre program and replaces three cells by
host inputs (`HOST_CELLS`): `07b` (ENV1) = `A0F0`, `088` (ENV2) = `A0F1`, `039` (LFO) = `A0F2`; the voice is fused
(one program). `bq_MODEL_tables.h`'s `BQ_PANEL_HOST` block has only the controls the voice keeps (`HOST_PANEL`:
CROSS MOD, OSC2 FINE, mix, cutoff, resonance, env amount, key track, HPF) and forces `HOST_WORDS`: Roland's LFO / ENV1
→ pitch off (the host does it), FLT LFO MOD 1 (`s1_lfo_filter()` is already octaves), PWM depth 1.2, LFO → AMP off
(`MODEL_host_init`). Until 2026-11-12 this was a second file `bq_MODEL_host_tables.h` (`bq_arm.py --host`); its
tables were the same as the exact build's, so one file now serves every build.

## 9. Oscillators at two sub-samples (`bq_host2x.c`, `bq_osc2x.h`, `make_voice.py --osc2x`)

Roland runs each oscillator at four sub-samples (176.4 kHz) with a 28-tap decimation FIR, 123–152 instructions per
oscillator. `bq_osc2x.h` keeps Roland's saw / pulse arithmetic at two sub-samples (192 kHz) and decimates with an
11-tap half-band FIR (`BQ_H0…BQ_H5`, least squares to Roland's one-pole roll-off at 12 kHz). `--osc2x` cuts the
lifted oscillators out (`OSC2X_CELLS`: `2019` = `A0F3`, `201e` = `A0F4`; their outputs `200a`, `200f`, `200b` read
back by `--kout`). Increments come from `s1_dt()` / `s1_rdt()` (no exp per sample); CROSS MOD multiplies OSC1's
increment by `s1_exp2(C04D × osc2)`. RANGE: OSC1 RANGE from the host (64′…2′ = −1…+4 octaves, both oscillators, as
SYSTEM-S1CC); OSC2 RANGE adds `2^(k2 − k1)` to OSC2 only. KEY TRACK reads the pitch without the range.

## 10. Filter coefficient and VCA on the ARM (`bq_arm.c`, `make_voice.py --arm`, `make_arm.py`)

Built with `examples/system_s1cc_boutique` (`ARM_CUSTOM`, its README §11). Of the voice, instructions 223…267 (cutoff
units `u` → coefficient `g`: a piecewise curve above 11, `e^(ln2 u − 3.2924) × 0.0036`, `2 sin / (sin + cos)`) and
321 (the VCA curve `max(0.444274 x³ − 0.005 + 0.186188 x, 0)`, `x = env2²`) move to the ARM's 1 ms tick:

```
u = 10.625 CUTOFF + 0.1666 + min((1 − RESO) / 2, 0.075) + ENV AMOUNT × env1² + KEY TRACK × (pitch − 4) + LFO octaves
g = table of u (−6…26, 1024 points, linear interpolation)      → the FILTER envelope's word (s1_env(1))
G = table of env2 (257 points)                                   → the AMP envelope's word (s1_env(0))
```

`make_arm.py` computes `g(u)` by following the lifted C operation by operation in double; tables are Q24 (no FPU on the
SYSTEM-1's ARM). `--arm` replaces cell `c_0b6` (g) by `A0F5` and `t321` (G) by `A0F6`; `bq_arm.c` smooths both with a
one-pole of 1 ms (`ARM_SMOOTH 0.0104`) so that the 1 ms steps do not zipper (−52 dB without it, gone with it, native
check 2026-11-11). Resonance and the rest of the filter stay on the DSP. Cost 315 → 253 per voice (4 voices).

```sh
python3 sdk/s1cc/examples/boutique_ported/tools/make_voice.py jp08 2 3 --host --osc2x --arm --names
python3 sdk/s1cc/examples/boutique_ported/tools/make_voice.py jp08 2 3 --host --osc2x --arm
python3 sdk/s1cc/examples/boutique_ported/tools/make_arm.py jp08
sdk/s1cc/s1cc build sdk/s1cc/examples/boutique_ported/bq_arm.c -o sdk/s1cc/build/bq_jp08a
sdk/s1cc/s1cc check sdk/s1cc/build/bq_jp08a --note 69 reso=200 mix1=255 mix2=128 xmod=40 hpf=128
KERNEL=sdk/s1cc/build/bq_jp08a sh examples/system_s1cc_boutique/build.sh
python3 tools/plugout_tool.py install plugins/JP-08-S1A --slot 1 --force --no-patches -y
```

The JP-08's own envelopes and LFO (`ARM_CUSTOM_ENV`, `ARM_CUSTOM_LFO`, 2026-11-11): `make_arm.py` also writes them,
from the exact tables (`bq_MODEL_tables.h`) and Roland's per-sample arithmetic (voice instructions 118…204, pre
14…49) as closed forms over one 1 ms step (96 samples):

| part | per sample (Roland) | on the ARM |
|---|---|---|
| attack | `x ← 1.05 − (1.05 − x)(1 − max(A, 7.927e-6))` until `x ≥ 0.8925` | factor^96 per step; the step it ends in sample by sample, the rest in decay |
| decay | `x ← s + (x − s)(0.99 + 0.01 max(1 − D, 1.2e-4))`, `s = 0.87 S + 0.02 max(max(1 − D, 1.2e-4) + 0.01, 1) − 0.02` | factor^96 |
| release | toward `t = 0.02 max(max(1 − R, 1.43e-4) + 0.01, 1) − 0.000708` | factor^96; done within 4e-6 of `t` |
| LFO rate | phase (span 2) `+= min(floor(RATE × 65536) × 2^-32, 0.0071359)` | per 1/16 step (6 samples); 0.044…37.3 Hz |
| LFO shapes | sine `(3.125 t² − 0.0416 t − 2.08 t³ − 0.504) × 2`, `t = |phase|`; triangle; saw down; square (JP-08 waves 0…3, words `C00C`, `C00D`, `C010`, `C00E`) | SHAPE positions 0…3; S&G / S&H stay the host's (JP-08 waves 4, 5 are not in the DSP program) |
| LFO delay | `y ← 1 − (1 − y)(0.9 + 0.1 DELAY)`, from 0 at each note; LFO × `max(5y − 4, 0)⁴` | per 1/16 step |
| LFO → FILTER | `C064` (±2.19 octaves at the ends) | the exact table (was the host's ±4) |

Native check against the per-sample recurrence (gcc, the header as is): envelopes within 1e-5, LFO frequency and
shapes exact, delay time within 1 %. LFO → PITCH stays the host's (±1 octave, `b |b|`: 0.25 at knob 64, Roland 0.242).

Panel map `bq_arm.panel` (30 of 39 lit): the drafted map misses what only the ARM reads (LFO → FILTER) and the
controls `panel_map.py` had no id for (CROSS MOD, HPF).

## 12. OSC1 / OSC2 WAVE: one program per wave pair (`JP-08-S1W`, `tools/make_waves.sh`) [2026-11-12]

## 13. Patches: the JP-08's patch files and what loading them takes [2026-11-12]

Goal: a JP-08 patch (a file the JP-08 wrote) loads into our PLUG-OUT and sounds as on the JP-08. This section is the
format and the gap list; no loader exists yet (§13.6).

Sources: the ARM image `PX-11:Appli` 1.21 decompiled with Ghidra (`work/ghidra/bq_appli`, functions named below),
the parameter table at `0x60066b1c`, the parameter info table at `0x6005a794`, the emulator `tools/bq_fw.py` for the
parameter words; the SYSTEM-1 OS 1.30 (`work/sys1_v130/app_master.bin`); the VST3 bundles' `Patch/*.bin`; the user's
SYSTEM-1 backup `BACKUP_live/PLUGOUT_PATCH*.PRM` (written by the device with SH-2 installed).

### 13.1 Files (`sys\backup_prm.cpp`, `sys\backup_util.cpp`) [code]

The Boutique's USB storage has two folders, `BACKUP` (the device writes) and `RESTORE` (the device reads at the
restore boot). Backup `0x600112d0` (mode `[0x60145ec0 + 0x10]` = 0), restore `0x600113ca`:

| file | count | contents | functions |
|---|---|---|---|
| `JP08_PATCH<n>.PRM` | n = 1…64, no zero padding | one patch: 43 parameters + name | write `0x600115ba`, read `0x600110d4` |
| `JP08_PATPRE<n>.PRM` | 1…8 (JP-08 only) | patch preset: `UPPER`, `LOWER` (0…64), `KEYMODE` (0…1), `PATPRE_NAME` 32 chars | `0x60012124` / `0x600121b6` |
| `BQ_PTN<n>.PRM` | 1…16 | sequencer pattern: `SCALE`, `LASTSTEP`, `SW1…`, 66 parameters (table `0x600676f6`), `PTN_NAME` 32 chars | `0x60011f74` / `0x60012006` |
| `JP08_USERAREA.BIN` | 1 | the raw flash user area `0x3300000`, `0x30000` bytes (mode 1); restore writes it back first if present and ≥ `0x30000` bytes, then reads the `.PRM` files | `0x600113ca` |

JU-06: `JU06_PATCH1…64.PRM`, 31 parameters (table `0x60066f7a`). JX-03: `JX03_PATCH<n>.PRM`, 39 parameters (table
`0x600672a0`), n = 1…16 or 1…32 (system parameter `0x22`), stored from patch memory 33 on. Mode 2 (debug) writes
`data_fact_patch_jp.inc` (`0x60011034`): every patch memory 1…127 as C, `{ // PATCH-%d` then `\t%d,\t// %3d: %s` for
the 321 parameter ids `0x18E…0x2CE` — the source form of Roland's factory data.

### 13.2 The `.PRM` record format [code]

Text, one record per parameter, in the order of the model's parameter table (26-byte entries: `u16` id + 16-byte
name + 8 zero bytes):

```
LFO RATE        (100);\r\n         name exactly as in the table: 16 characters, padded with spaces
OSC2 TUNE       (128);\r\n         value: decimal, '-' allowed, no leading zeros (0x60011b68)
...
PATCH_NAME(JP-08 PATCH 1   );     last record: 16 characters (ids 0x27F…0x28E), no "\r\n" after it
```

Reader `0x600110d4` + `0x60011664`:
- reads byte by byte into a 128-byte line; `;` ends a record; any byte outside `0x20…0x7E` (CR, LF) or a line over
  127 bytes throws the partial line away;
- a record matches parameter k when the table name occurs in it and the first `(` sits exactly 16 characters
  (the padded name's length) after it: `LFO_RATE(100);` or `LFO RATE(100);` do **not** load;
- value: optional `-`, then digits up to `)`; a non-digit drops the record;
- every parameter starts at its **default** (info table `+8`), not at the patch in memory: a file with missing
  records gives defaults for them; a value outside min…max (info `+0`, `+4`) also becomes the default;
- `PATCH_NAME`: `(` right after the 10 letters; the bytes up to `)` are copied over 16 spaces (a longer name runs
  over the 16-byte buffer — keep names ≤ 16).

The SYSTEM-1 OS writes the same records with the same code (strings `PATCH_NAME`, `(%d);\r\n`,
`data_fact_patch_system1_bank%d.inc` at `0xdc6a…0xdd18` of `app_master.bin`, table of 26-byte entries at `0x5b15c`)
but its names are `\0`-terminated with underscores (`LFO_RATE(97);`), so the two kinds of file do not load into each
other.

### 13.4 What "faithful" asks of our PLUG-OUT

The tables (`bq_jp08_tables.h`) are indexed by the JP-08 value itself: row v = the words Roland writes for value v.
A loaded value can therefore select its row directly, and every "exact" row above is bit for bit Roland's (with the
44.1 → 96 kHz rate conversion, §3). Three things stand between a JP-08 file and that:
1. **Bipolar knobs.** `bi` reads row `2 |knob − 128|`: odd JP-08 values have no knob position, and 255 is
   reachable only on the negative side. OSC LFO MOD, OSC ENV MOD, FLT ENV MOD and FLT LFO MOD are unipolar on the
   JP-08 (0–255); through the S1 panel they load as `128 + v / 2` and lose their lowest bit.
2. **Parameters without a SYSTEM-1 control** (the bold rows): they need a place in the SYSTEM-1 patch (§13.5:
   `PLUGOUT_EXTEND01…40`) and code in the PLUG-OUT that applies them.
3. **The host's parts** (S1A): LFO → PITCH and the pitch envelope are SYSTEM-S1CC's, not `C04A` / `C04B`.

### 13.5 How patches are stored for a SYSTEM-1 PLUG-OUT (SH-101, SH-2, PROMARS, SYSTEM-100) [code + measured]

The question "are the PLUG-OUTs' patches the same?": **yes, all the SYSTEM-1 PLUG-OUTs share one patch layout**, the
SYSTEM-1's own; the PLUG-OUT code holds no patch format (no `.PRM` names in their regions).

- **Bank files** `plugins/<NAME>/Patch/*.bin` (installed with the PLUG-OUT; `tools/patches.py`, Vol. IV ch. 4
  "Bank files"): `KoaBankFile00002` (`00001` for PROMARS: same size, not read by `patches.py` yet), tag `PG-SH101` /
  `PG-SH2` / `PG-PRMRS` / `PG-SYS100` / `PG-SYSTEM1`, 64 records of 16 (name) + 27 (header) + 640 bytes. The 640
  bytes are `Script.xml`'s struct `patch`: 64 values `int2x4` (one byte as two nibbles), the name (16 characters as
  nibbles), 48 values `int8x4` (32-bit, two's complement, eight nibbles). The value types and offsets of the five
  `Script.xml` are identical; only the labels differ (`MODULATOR RATE` on the SH-101 = `LFO RATE` on the SYSTEM-1;
  labels in parentheses = not used by that model).
- **The SYSTEM-1 `.PRM`** (`SYSTEM1_PATCH<n>.PRM`, `PLUGOUT_PATCH<n>.PRM`, n = 1…64): the same 112 values with the
  OS's names (table `0x5b15c`, ids `0x160…0x19F` = the 64 panel values `LFO_WAVE … OSC2_EX`, `0x1B0…0x1B7` =
  `INPUT_JACK_SW … CTRL_HOLD`, `0x1B8…0x1DF` = `PLUGOUT_EXTEND01…40`), then `PATCH_NAME`. These ids are the ones the
  PLUG-OUT receives (CROSS MOD `0x16B`, HPF `0x180`, OSC2 SYNC LED `0x172` were measured on the device before this
  table was read: they agree).
- **Measured** (2026-11-12): `BACKUP_live/PLUGOUT_PATCH*.PRM` against `plugins/SH-2/Patch/1 Preset.bin`, matched by
  name: 37 patches, 29 identical in all 112 values but one, the other 8 differ only in ARP / SCATTER / HOLD / TEMPO
  SYNC (performance switches saved on the device). The one: `OSC2_COARSE` = bank byte − 11 (the bank stores
  `value − min`, the `.PRM` the signed value, here −11…+11). Other signed parameters may have the same offset.
- Each model uses the EXTEND values for its own parameters (SH-2: `LFO CV GAIN`, `ENV1 KEY FOLLOW`, `OSC1 VARIATION`,
  `REVERB TIME`…; SYSTEM-100: `S&H MODE`, `LFO-2 FREQUENCY`, cable colors…; SYSTEM-1: unused, "EXTEND PRMnn for
  PLUGOUT").

The SYSTEM-8 PLUG-OUTs (JUNO-60, JX-3P, JUPITER-8…) use `KoaBankFile00003` with `patch` + `patch2` + `patch3`
(20 223 bytes per record): another layout, not the one for this port.

So a JP-08 patch on our SYSTEM-1 PLUG-OUT is a SYSTEM-1 patch: the JP-08 values that have a SYSTEM-1 control go into
its panel value (inverse of `PANEL` in `tools/bq_arm.py`: `uni` = v, `rev` = 255 − v, `bi` = 128 ± v / 2), the rest
into `PLUGOUT_EXTEND` slots. Proposed slots (unproven: that the PLUG-OUT receives EXTEND values is **not measured**):

| EXTEND | JP-08 | why |
|---|---|---|
| 01–04 | OSC LFO MOD, OSC ENV MOD, FLT ENV MOD, FLT LFO MOD (exact 0–255) | §13.4 point 1 |
| 05 | OSC FREQ MOD DST | no control |
| 06 | FLT LPF SLOPE | |
| 07 | FLT ENV MOD SRC | |
| 08 | AMP LEVEL | |
| 09 | AMP LFO MOD | |
| 10 | ENV1 POLARITY | |
| 11 | ENV2 KEY FOLLOW | |
| 12 | OSC2 RANGE (0–255) | the S1's OSC2_RANGE has fewer positions |
| 13 | ASSIGN MODE | |

LFO WAVE, OSC1 / OSC2 WAVE, OSC1 RANGE, OSC2 SYNC, PORTA, BEND RANGE, DELAY have SYSTEM-1 values (`LFO_WAVE`,
`OSC1_WAVE`, `OSC2_WAVE`, `OSC1_RANGE`, `OSC2_SYNC`, `PORTAMENTO`, `BEND_RANGE`, `DELAY` / `DELAY_TM`); their value
mapping follows the panel of the build (§4, §12), DELAY's 0–15 against the S1's 0–255 is open.

### 13.6 Where the JP-08's factory patches are, and next steps

**Not in `BQ_UPD.BIN`** [code + search]: without stored data the patch memory starts at the info-table defaults
(`0x0100d7f6` → `0x0100d4e0`, ITCM: every value = `+8` of its info entry); no table of 43 / 31 / 39 values in range
exists in the image (searched as 8-, 16-, 32-bit arrays, ≥ 8 consecutive records), and the update image's other
modules are the updater and the sub-CPU. The factory sounds live in the device's flash user area (`0x3300000`,
written at the factory): they come out only by a BACKUP on a JP-08 (`BACKUP/JP08_PATCH1…64.PRM`, or
`JP08_USERAREA.BIN`) or from Roland's published backup data. None is in this repository or the user's files yet.
