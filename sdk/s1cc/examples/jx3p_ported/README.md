# jx3p_ported — the JX-3P voice on SYSTEM-S1CC-BOUTIQUE, own oscillators, 8 voices

State: 2026-11-17. The voice of the SYSTEM-8 JX-3P PLUG-OUT (1.01) as an s1cc kernel for the SYSTEM-1
(`examples/system_s1cc_boutique`, `ARM_CUSTOM`): Roland's filter, VCA and output stage lifted from the microcode

Roland's microcode as is: 1 DCO, 4 voices, hung slave B).

## 1. Source

`plugins/JX-3P` = the user's SYSTEM-8 JX-3P PLUG-OUT 1.01. `Script/Code8_1.Dat` region 1 holds the DSP programs, cut
by `examples/from_scratch/engine/programs.py` (each SHA-256 checked); the ARM engine is what
`tools/plugout_dsp_tables.py` runs to record the words every parameter value writes. No Roland byte is in this
folder's sources: the lifts are C expressions of the programs, the tables are values.

## 2. The voice program (`tools/make_voice.py`)

On the SYSTEM-8 one voice runs on three DSPs of a slave: DSP0 MAIN0 (LFO, ENV1, ENV2, pitch) → DSP2 MAIN2 (relays
MAIN0's words to the DCO slots, mixer) + the DCO1 / DCO2 slot programs → DSP4 MAIN4 (VCF, VCA, the pair's sum).
MAIN0 is not lifted: its work is the ARM's (§3). MAIN2, DCO1, DCO2 and MAIN4 become one program in the order they
run in a sample, every literal address rewritten (`make_voice.py` docstring: the bank and MXM maps), then lifted:

| lift | `--kout` / `--cell-in` | what it is |
|---|---|---|
| `jx3p_voice.h` | `231e` | the whole voice (voice A of the pair) |
| `jx3p_core_voice.h` | `231e`; `CORE_CELLS` | the core: cells cut to inputs `A0C0` DCO1 out, `A0C2` DCO2 out, `A0C4` the filter's g (MAIN4 cell `025f`, instructions 881…969), `A0C5` the VCA's input term (cell `028e`, 1047…1050) |
| `jx3p_dco1_saw.h` … | `221f,221b,2221,221d`; `DCO_IN` | one DCO program alone, its mailbox words as inputs `A0D0` pitch … `A0D4` wave |

```sh
python3 sdk/s1cc/examples/jx3p_ported/tools/make_voice.py            # the lifts (DCO1 saw, DCO2 saw program)
python3 sdk/s1cc/examples/jx3p_ported/tools/make_voice.py --check    # the joined program against the emulator
```

### 2.1 Names (two steps)

As in `boutique_ported` §2.1: `make_voice.py --names` writes `jx3p_*_names.txt` with
`dsplift_names.py` from the seeds (`jx3p_names.txt` + the panel's parameter names from `work/jx3p/jx_arm.json`);
the lifts only read those files.

### 2.2 What the core reads besides its inputs [measured on the default patch]

The S8 engine's per-voice words of DSP4 (`docs/vol3_voice_allocation_scheduling/system8_voice_allocation.md` §4):
`A02A` gate (written 1 at the first note on and never cleared: `s1jx.note_writes`) and `A029` velocity curve, read as
`A06A` / `A069` after the map. `A069` enters through `XFADE(C130, A069, C12F)` with `C12F = 0`: unused. The kernel
gives `A06A = 1` (`jx3p.c` `jx_in`). Constant parameter words (`s1jx.model_writes(default_vals())`): `C130 = 0.93`
(the VCA level the slew limiter of instructions 1015…1029 moves to: 0 → 0.93 in ~3 ms at a voice's first sample),
`C12A = −0.503937`, `C129 = 0` (velocity → cutoff off), `C14B = 1.005361` (VCA LEVEL, applied to the kernel's output).

## 3. The ARM side (`tools/make_arm.py` → `jx3p_arm.h`, `jx3p_tables.h`)

`tools/jx_arm.py` runs `tools/plugout_dsp_tables.py` on `plugins/JX-3P` (DSPs 0, 2, 4) → `work/jx3p/jx_arm.json`: for
every parameter (ids from `0x6CD`) and every value 0…255 the words it writes. `make_arm.py` turns the rows into
Q24 tables and writes Roland's formulas as integer code for `engine.c`'s 1 ms tick (`ARM_CUSTOM`,
`examples/system_s1cc_boutique/README.md` §11):

| value | formula (lifted instructions) | written to |
|---|---|---|
| filter u | `11.6 vcf(CUTOFF) − 0.7 + C12B + min((1 − RES) 0.5, 0.075) + BRILLIANCE + LFO × VCF LFO MOD + ENV1 term × VCF ENV1 MOD + (note − 60)/12 × PITCH FOLLOW`; `vcf(c) = clamp(0.65628016 c + 0.6643478 c² − 0.32077295 c³, 0, 1)` (881…934) | — |
| g | `u` limited to −3…11.5, `w = e^(u ln2 − 3.292449) × 0.014398932`, `g = min(tan w / (1 + tan w), 1)` (935…969): table `arm_g`, 1/64 octave, linear | `s1_env(1)` (ramp) |
| VCA | ENV2 × 0.013004484 (1050) | `s1_env(0)` (ramp) |
| ENV1 term | `env × m (1 − 2 pol) + m pol` (50, 916): `pol` = the row's polarity word (`A02D` / `A066`) | — |
| DCO1 pitch | `(note − 12)/12 + ARM_S1_OCT + A024 + RANGE1 + FREQ MOD (LFO × DCO LFO MOD, ENV1 term × DCO ENV1 MOD) + bend × 2/12`, then `t + clamp(0.0004 floor t − 0.0016, −1e-4, 1e-3)`, limited to −4…10 (38…74) | `s1_dt` = 2^(t − 4.75) × 440/96000, `s1_rdt` |
| DCO2 pitch | the same with `A025` (8.3e-5), RANGE2, TUNE, FINE TUNE and its own FREQ MOD | `s1_pitch` = its step (a float word), `s1_arm(0)` = dt1/dt2/256 (BLEP width only) |

`ARM_S1_OCT` = 1 octave: the SYSTEM-1 plays every RANGE position one octave above the S8 JX-3P's scale [measured
2026-11-17, note 60, the same panel: stock SYSTEM-1 524.0 Hz (`work/jx3p/ref_capture/system1_saw_mix50_vol50_note60.raw`),
JX-3P-S1 without it 261.5 Hz (`jx3p_s1_saw_*_note60_*.raw`)]. Roland's S8 engine writes `(note − 12)/12` (note 60 →
4.0, read in its engine with `tools/plugout_dsp_tables.py`'s `Engine`, id `0x429`) and its DCO plays 4.75 as A 440
(`osc_check.c`), so the S8 JX-3P at 8' plays note 60 at 261.6 Hz: the octave is the SYSTEM-1's convention, not an error
of the lift. `tools/arm_check.c` sets `ARM_S1_OCT` 0 (Roland's scale).

The kernel smooths g with Roland's one-pole of instruction 922 (0.0065235896 per sample; Roland applies it to the
sum before the exp, here to g). BEND RANGE is the JX-3P default, 2 semitones (parameter `0x700`).

### 3.1 Why DCO2's step is a float word, and S1_REF_INPUTS

A Q24 ratio dt2/dt1 is exact only near 1: with RANGE −3…+2 on each DCO, TUNE and the modulations, DCO2 can be more
than 8 octaves from DCO1 (2026-11-17, `arm_check.c`: with a ±4-octave ratio, 8 of 61 cases were 350…1850 cents
off). The ARM writes DCO2's step itself into the voice's pitch word (`B5_PITCH`, IEEE bits; `LFO_PITCH=0`, so the
host does not touch it); only the BLEP width goes through the ramp word, where 3e-4 relative is enough.

The first build on the device (2026-11-17) had OSC2 MIX doing nothing: s1cc takes every value's range from its native
reference run, where `s1_arm(0)` was 0 and `s1_pitch()` was the note in octaves, so DCO2's BLEP and step were scaled
for values the device never has, and overflowed there (`s1cc check` with OSC2 alone: −5.8 dB). The SDK now lets a
kernel say what those words hold on the device (`S1_REF_INPUTS`, `s1dsp.h`: `s1_ref_pitch`, `s1_ref_arm`; `s1rt.c`,
`s1check.py` bench, `s1cc` keeps the two functions); `jx3p.c` defines them for the default patch. With them: 28.6 dB,
as DCO1, and every pair cheaper (worst 233 → 224 units). An exponential on the DSP instead (`dt2 = dt1 2^x`) cost
22 units per voice (measured): the worst pair would not fit 8 voices.

| PLUGOUT_EXTEND01…08 `0x1B8…0x1BF` | VCA MODE, VCA LEVEL, BEND RANGE, BEND GAIN, BEND SENS DCO, BEND SENS VCF, MOD SENS DCO, MOD SENS VCF (§3.7): value − default, patch only |

| OSC1 / OSC2 COLOR MOD `0x169` / `0x16E` | DCO1 / DCO2 FREQ MOD: MANUAL = LFO + ENV, LFO = LFO, PITCH ENV / FILTER ENV / AMP ENV = ENV, SUB OSC = off |
| OSC1 / OSC2 MIX `0x174` / `0x175` | DCO1 / DCO2 LEVEL (`C034` / `C035`, kernel tables `lvl1` / `lvl2`) |

| LFO SHAPE, RATE, FADE, KEY TRIG | the JX-3P's LFO on the ARM (§3.5) |

Polarity (2026-11-17): Roland's rows of the JX-3P are bipolar (0 at 128) for VCF / DCO LFO MOD, VCF / DCO ENV1 MOD,
PITCH FOLLOW and BRILLIANCE. The SYSTEM-1 knobs LFO TO PITCH, LFO TO FILTER, FILTER ENV AMOUNT and PITCH ENV AMOUNT
are bipolar too (128 = 0: `examples/system_1_synth/README.md` §11, `docs/vol1_system_architecture/
bus_interconnect.md` §16.6), so those rows are used as they are. KEY TRACK is unipolar on the SYSTEM-1: knob k →
row 128 + k/2 (Roland's negative key follow is not reachable). The ARM's knob defaults (`ARM_CUSTOM_INIT`) are the
JX-3P defaults of `jx_arm.json`; the panel's real values arrive at selection (`model.c` `resend_panel`).
The OSC COLOR MOD mapping and the semitone mapping of COARSE are panel choices, not values of Roland's.

### 3.4 Envelopes (`ARM_CUSTOM_ENV`) [2026-11-17]

The JX-3P's ENV1 / ENV2 are MAIN0's (instructions 155…253, the same code for both, read from the lift with jumps
`work/jx3p/main0_m.c`), not the host's ADSR:

| | MAIN0 | ARM (`jx3p_arm.h` `arm_custom_env`) |
|---|---|---|
| rate | once per 192 samples (a counter + 0x1.555555p-8 per sample); the value held in between; first tick at the note on | once per 2 steps of 1 ms (192 samples), the first at the note on |
| attack | `x = min(x + A, 1)` (linear), then decay | the same, Q24 |
| decay | `x = max(S + (x − S)(1 − D) − 1.49999e-5 (0.5 − x), S)` | the same |
| release | `x = max(x (1 − R) − 1.49999e-5 (0.5 − x), 0)` | the same; at 0 the voice's envelope stops |

A, D, S, R: Roland's rows (`jx_arm.json`; ENV1's and ENV2's are equal, checked by `make_arm.py`), fader 0…255 =
row. AMP faders → ENV2 (the VCA), FILTER faders → ENV1 (filter and DCO ENV MOD).

Check (`tools/env_ref.py` → `tools/env_check.c`): MAIN0 in the emulator (the S8 chain with Roland's programs), 6
settings (instant attack; A/D/S/R 128; sustain 0; long release …), 700 ticks each, note off at tick 400: largest
difference 6.5e-4 (the DSP's own quantization in decay / release). The reference chain's model (`examples/from_scratch`)
writes slightly other ENV words than Roland's ARM (ATTACK 128: 0.0035784 against 0.0035947 in `jx_arm.json`):
`env_ref.py` writes `jx_arm.json`'s words so that both sides use the same.

LFO: still the host's (`ARM_LFO`); MAIN0's LFO (instructions 66…147: one LFO for all voices, rate
`0.46623794 e^(5.28342146 k) − 0.413383555`, sine `1.3674 t + 1.8136 t² − 1.181 t³`, square, sample & hold, delay) is
the next step.

### 3.5 LFO (`ARM_CUSTOM_TICK`, `ARM_CUSTOM_GATE`) [2026-11-17]

MAIN0's LFO (instructions 66…147), one for all voices, on the ARM sample by sample (`arm_custom_tick`: 6 m samples per
tick, a few operations each):

| | MAIN0 | ARM |
|---|---|---|
| rate | `f = 0.46623794 e^(5.28342146 k) − 0.413383555` (k = RATE row, `C026`), phase step `min(f 2^-16, 0.0155343)` per sample, span 2 (−1…1); × 2 for RANDOM (`A02C`) | `arm_jl_inc`, uint32 phase (2^32 = span 2) |
| SINE | `1.3674 t + 1.8136 t² − 1.181 t³ − 1`, `t = |wrap(phase + 1)|`, **held**: taken again when a counter (+ `max(4 step, 0.0010212418)` per sample) reaches 1 or the phase changes sign. 8 steps per cycle when fast, one per ~979 samples when slow: the JX-3P's CPU LFO | the same |
| SQUARE | `sign(phase)`, every sample | the same |
| RANDOM | the master's noise word (bank 1 `2201`) at each wrap | an LCG at each wrap (the emulator has no noise: not compared) |
| delay | per voice from the note on: `+ A02D` per sample up to 1 | `arm_jl_fade`, Q31 |
| depth | × (delay + 1 − `C027`): DELAY 0 has `C027` = 0, so **× 2** (±2); any other DELAY ends at ±1 | the same |
| KEY TRIG | `A02A` | the SYSTEM-1 LFO KEY TRIG button (`lfo_kt`): the phase from 0 at the note on, the first value at once |

The voice's DCO / VCF LFO MOD rows multiply this ±2 word (`A0A5`), as on the S8; the host's LFO (±1) gave half the
depth. Panel: LFO RATE → RATE, LFO FADE → DELAY TIME, LFO SHAPE 0 sine / 1 triangle / 2 saw → SINE, 3 square → SQUARE,
4 sample & glide / 5 sample & hold → RANDOM (a panel choice).

Check (`tools/lfo_ref.py` → `tools/lfo_check.c`): MAIN0 in the emulator with `jx_arm.json`'s words, 7 cases (rates 60,
100, 175, 230; delays 0, 60, 128; sine and square): over the first 12000 samples, each sample within ±2 samples of
Roland's: largest difference 3.8e-3; periods equal (2.5e-5 at RATE 100); peaks equal. Later the step instants drift
apart by a few samples (the phase step in the DSP's rounding against ours: ~0.4 sample per cycle at RATE 175).

The engine (`examples/system_s1cc_boutique/engine.c`) calls two new optional hooks of the ARM_CUSTOM header:
`arm_custom_tick(samples)` once per tick before the voices, `arm_custom_gate(v, on)` at every note on / off.

### 3.7 Bend and modulation [code: Roland's engine in unicorn; checked by `tools/arm_check.c`] (2026-11-17)

Roland's engine (`tools/plugout_dsp_tables.py`'s `Engine`, the part state `0x22C` / `0x519` = 0 first: the
sensitivities are 0 until then) writes, for voice A of each DSP (B: + 0x16, DSP5 + 0x80):

| word | value | from |
|---|---|---|
| DCO `C022`, filter `C122` | bend / 8192, −1…1 | the bend lever (S8 id `0x465`) |
| DCO `C024`, filter `C124` | mod / 255 | the mod lever (S8 id `0x467`, 0…255) |
| DCO `C023` | BEND SENS DCO / 255 × (BEND RANGE + 1) / 12 × (BEND GAIN + 1) | `0x739`, `0x700`, `0x738` |
| filter `C123` | BEND SENS VCF / 255 × (BEND RANGE + 1) / 12 × (BEND GAIN + 1) | `0x73A` |
| DCO `C025` | MOD SENS DCO / 255 | `0x73B` |
| filter `C125` | MOD SENS VCF / 255 × 10 | `0x73C` |

The voice (`jx3p_voice.h`): both DCOs' pitch + `C022 C023` + `A0A6 C024 C025` (instructions 47, 56…58), the
cutoff's sum + `C122 C123` + `A0A6 C124 C125` (916, 920). `A0A6` is MAIN0's LFO wave alone: ±1, no delay, not × 2
(`work/jx3p/lfo_ref.npz`: `A0A6` = `A0A5` / 2 at DELAY 0 and full from the first sample at any DELAY).

Ours (`jx3p_arm.h` `jx_bend`, `jx_mod`, `jl_raw`): bend = `cust_bend` (id `0x130`), mod = `cust_mod` (id `0x131`,
`model.c` CC 1, 0…127) / 127; the six JX-3P values in PLUGOUT_EXTEND03…08 (value − default, as EXTEND01 / 02):
BEND RANGE (2), BEND GAIN (0), BEND SENS DCO (255), BEND SENS VCF (255), MOD SENS DCO (128), MOD SENS VCF (128). With
the defaults a full bend is 3 semitones (before: a fixed 2). `tools/arm_check.c`: 40 of its 61 cases with random
bend, mod and the six values against the lift with Roland's words: g within 2.9e-5, DCO1 0.12 cents, DCO2 0.004
cents (the same as without). Installed 2026-11-17 with the 64-patch bank, not heard; `0x131` reaching the
  slave's engine is not measured.

## 4. Oscillators (`jx3p_osc.h`)

### 4.1 Roland's three waveforms and ours [measured on the lifts, 2026-11-17]

Roland's DCO programs run four sub-samples per sample (384 kHz): phase, a rounded edge (`sin(π/2 clamp(…))`), a
28-tap decimation FIR, then the output stage, ~120 instructions each. The JX-3P's WAVEFORM positions are not saw /
square; rendering the lifts natively gives:

| position | Roland | ours (one sample per sample) |
|---|---|---|
| 0 SAW | saw program, wave word 0: the phase, the tilt `0.8532445 y1 + 0.44227272 x − 0.29551718 x1`, × −0.5 (the FIR inverts: a rising saw) | `2p − 1` − PolyBLEP, the same tilt, × 0.5 |
| 1 SQUARE | the sqr slot program (its own): `−sign(phase) + 0.5 × 0.98ⁿ` (a spike after every edge, n sub-samples), a one-pole / one-zero per sub-sample (0.79069895, 0.7385094, −0.52920836), × 0.33 | ±1 with two PolyBLEPs, the spike `0.92236816` (= 0.98⁴) per sample reset at each edge, the filter's 96 kHz equivalent (pole and zero to the 4th power, DC gain 1) |

| DCO2 3 NOISE | the noise slot program outputs 0; MAIN2 takes the master's noise word (IOMD `60E2`) | ours: a Weyl sequence through a squaring hash, ±1 |

`tools/osc_check.c` (one build per waveform, command in its header): harmonics 1…8 of ours within 0.1…0.7 dB of
Roland's from 28 Hz to 1760 Hz for all three; SNR after alignment 35 / 33 / 23 dB at 110 Hz (the rest is the FIR's
fractional delay). At 5 kHz ours keeps up to ~25 dB more of harmonics 5…8: the 28-tap FIR's roll-off above ~15 kHz
is not modelled.

The forms that s1cc compiles cheaply (2026-11-17, by C line with `s1cc build --debug`): a wrap written
`x >= 1 ? x - 1 : x` (an exact mod); the BLEP with `x = t rd` and `(1 − t) rd = rd − x` (`rm = rd − 1` once per
oscillator); the spike's edge from the sign of the BLEP's after-edge terms (`s1_sign(a_p + a_q)`, 1 op) instead of a
comparison; the output gain folded into the filter's coefficients. SQUARE + SQUARE went from 269 to 233 units, every
pair to 8 voices. Native output unchanged.

### 4.2 Wave pairs (`tools/make_waves.sh`)

One kernel per pair (`JX_DCO1` 0…2, `JX_DCO2` 0…3: 12 kernels, `waves/jx3p_wAB.c`), joined by
`build_multi.sh SECT_SWITCH=1` as the JP-08 port (`boutique_ported` README §12): moving OSC1 / OSC2 WAVE places

### 4.3 DCO2 CROSS MOD: the OSC2 SYNC / OSC2 RING buttons [code]

The JX-3P's DCO2 CROSS MOD (off / SYNC / METAL) on the SYSTEM-1's two buttons, one choice at a time:

| SYSTEM-1 | word (LED) | JX-3P | voice input |
|---|---|---|---|
| OSC2 SYNC (CC 112) | `0x172` | SYNC | `A028` = 1 |
| OSC2 RING (CC 111) | `0x171` | METAL | `A028` = 1, `A029` = 1 |
| both off | — | off | `A028` = `A029` = 0 |

`model.c` (`ARM_CUSTOM_XMOD`) keeps the state: a press of the lit button turns it off, a press of the other moves the
choice there; it writes both words (`send_xmod`), so one LED at most. The words reach the kernel as `S1_PARAM`
`xsync` / `xmetal` (`jx3p.c`); DCO2 reads DCO1's wrap mark of the sample before, as MAIN2 hands it (`jx_mark`,
checked by `tools/xmod_check.c` against Roland's DCO2 saw program). A patch keeps the two words; at a patch change
the engine's refresh applies them and the model's (`m_refresh` / `m_store`) takes its copy back from them.

### 8.4 Where it can run (open)

About 40 instructions per sample and two delay lines (L, R: one request each). The slaves have no delay memory for
our programs (only bank-0 rings, < 2048 samples: 675 needed, so an indexed bank-0 line would fit); master DSP B has
the delay memory through `S1_MASTER` / `s1_line_tap` (6 requests per sample, `EDM_LINES`), but `S1_MASTER` runs per
voice, the chorus once on the mix. Not decided.

Open: the output stage's undecoded instruction; the sign of the ±2⁻²¹ term; the hiss (EFFECT TONE); the fade-in; the
BBD clocking's own aliasing; a comparison against the S8 itself (a capture of the S8 JX-3P with the chorus on).
